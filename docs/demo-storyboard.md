# GreenFlow presentation storyboard

Target duration after all MVP phases: 5–7 minutes. Scenes 0–6 now have complete on-chain enforcement and actor-signed browser controls, receipt views, evidence hashing, servicing reconciliation, and a reproducible E2E gate.

| Scene | Presenter action | Message | Delivery phase |
|---|---|---|---:|
| 0. Setup | Open `/demo`, inspect the local/mock disclosure and switch fictional actors. | Deterministic, honest teaching environment. | 0 |
| 1. Investment | Alice buys 6; Charlie is blocked; Bob buys 4. | Eligibility constrains token ownership. | 3 |
| 2. Project | Issuer proposes PROJECT-001; verifier authorizes its policy. | Issuer cannot self-authorize proceeds. | 3 |
| 3. Invalid spend | Try before policy, UnknownVendor, and above the M1 limit. | Controls prevent funds from moving. | 3 |
| 4. Verify and pay | Verifier inspects evidence and approves M1; 300 mock USD reaches SolarSupply atomically. | The control operates at payment time. | 3 |
| 5. Oversight | Investor inspects budgets, evidence digest, events, and remaining 700. | Chain-derived transaction-level traceability. | 3 |
| 6. Service bond | Issuer funds 1,050 separately; admin advances the fictional clock; Alice claims 630 and Bob claims 420; all 10 units retire. | Debt service is separate from green proceeds; the treasury remains 700. | 4 |
| 7. Wrap | Compare prevention with retrospective reporting and state limitations. | GreenFlow's differentiated value and truthful boundary. | 5 |

Core presentation line: “GreenFlow does not just put a green bond on-chain. It checks the permitted project, vendor, milestone and budget before money leaves the treasury, and then makes the outcome auditable by investors.”
